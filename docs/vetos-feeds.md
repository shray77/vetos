# VetOS Feed Convention · v1

Как любой проект экосистемы отдаёт живые данные лаунчеру — без серверов,
без личных кабинетов, без API-ключей. **Git — это бекенд.**

## Принцип

Вет-контур — студенческая экосистема: бекенды только статические
(GitHub/GitLab Pages, raw-файлы репозиториев). Поэтому «локальный API
проекта» = **компактный JSON-срез, лежащий в git рядом с данными проекта**.
CI-бот или скрипт проекта его обновляет, VetOS тянет и рендерит нативно.

Формула: `данные проекта → CI/скрипт → JSON в git → raw.githubusercontent
→ VetOS FeedService → карточка на домашнем экране`.

## Правила среза

1. **Компактность** — один файл ≤ 16 КБ. Лаунчер качает его в мобильной
   сети: без истории, без сырых массивов, только агрегаты и топ-строки.
2. **Стабильная схема** — поля не переименовываются, новые добавляются
   опционально. Лаунчер парсит толерантно: отсутствующее поле = «—»,
   а не падение.
3. **Метка времени** — `generatedAt` (ISO-8601) или `updated` (дата),
   чтобы карточка могла показать «обновлено 07.09».
4. **Человекочитаемые строки** — лаунчер показывает как есть: сначала
   готовый `digest: []`, а не формулы на клиенте.
5. **URL** — `https://raw.githubusercontent.com/<user>/<repo>/<branch>/<path>`.
   Кэш CDN ~5 мин — для тапа «обновить» и фоновых таймеров этого хватает.
6. **Обновляемость** — срез должен реально обновляться (Actions-метроном,
   cron, ручной коммит). Протухший срез честно показывает свою дату.

## Подключено (v0.3.0)

| Фид | Источник | Что на карточке |
|-----|----------|-----------------|
| Прогноз 7 дней | `vet-meteo/data/outlook.json` | THI по дням станции (наследует станцию метео-тайла), дни >72/>80 |
| Вспышки · ВетКарта | `vet-meteo/docs/data/outbreaks.json` | свежие вспышки Ростовской обл., всего записей, дата курации |
| Прогноз vs факт | `vet-meteo/data/verify.json` | вердикт расхождений, MAE THI, окно проверки |
| Недельный дайджест | `vet-meteo/data/weekly.json` | строки-выводы по архиву радара |

Отключаются в настройках VetOS (по умолчанию все, кроме недельного).

## Как подключить новый проект

1. В репо проекта завести файл среза, например `data/vetos.json`:

   ```json
   {
     "generatedAt": "2026-09-10T06:00:00Z",
     "cards": [
       {"title": "Суть строки", "value": "12.3", "hint": "обновлено утром"}
     ],
     "digest": ["вывод 1", "вывод 2"]
   }
   ```

2. Обновлять его из CI/скрипта проекта (как метроном vet-meteo).
3. В VetOS: добавить модель в `lib/models/feeds.dart`, фид в
   `FeedService.refresh()` и карточку в `lib/widgets/feed_cards.dart`.

### Кандидаты

- **VetVoice**: как только проект поднимется — срез
  «справочник дозировок: топ-препараты дня» или «последние протоколы».
  Дозировка по голосу остаётся в приложении, а лента даёт quick-reference.
- **VetEco (vetvoice-rag)**: «дайджест медкарты за смену» — агрегат без
  персональных данных, или счётчики шаблонов протоколов.
- **VetLearn (gitlab)**: тот же паттерн через raw GitLab
  (`gitlab.com/<user>/<repo>/-/raw/main/feed.json`) — список свежих
  материалов/треков; CI GitLab обновляет.

## Чего в конвенции нет (и почему)

- **Двусторонность (запись)**: git-статика не принимает POST. Когда
  понадобится «отметить прочитанным / сохранить протокол» — это локально
  в SharedPreferences VetOS либо отдельный сервис, когда он появится.
- **Авторизация**: личных кабинетов нет по дизайну; всё, что в срезе,
  должно быть публичным. Персональное — только на устройстве.
- **Push-обновления**: лента опрашивает по таймеру (интервал 10–60 мин
  из настроек). Push без своего сервера не сделать.

## Дорога дальше (v0.4+)

- Горизонтальная лента → «стена» карточек с группировкой по проектам.
- Шорткаты проектов по долгому тапу (нативный ShortcutManager).
- AppWidgetHost: настоящие Android-виджеты на домашнем экране VetOS —
  тогда каждый проект сможет выпускать свои виджеты по той же конвенции.
